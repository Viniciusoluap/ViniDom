## Story

**Como** administrador, **quero** conectar meu número ao WhatsApp Web por QR Code na aba WhatsApp do painel, **para que** o estado da conexão e o QR Code apareçam de fato e eu possa concluir o pareamento.

## Acceptance Criteria

1. A URL configurada para WhatsApp Web responde `GET /health` com JSON `{ "ok": true }` do serviço `whatsapp-service`, e não com HTML do site.
2. O serviço permanece ativo no ambiente Railway; `GET /status` e `GET /qr` autenticados funcionam através de `api/whatsapp-web.js` sem expor o segredo no navegador.
3. Quando o estado é `qr_pending`, o painel mostra o QR Code atualizado e instruções para escanear; após escanear, mostra `connected` e o número da sessão. Erros de rede, segredo divergente e URL incorreta têm mensagens e ações coerentes.
4. O pareamento permanece após reinício do serviço, com credenciais guardadas em armazenamento persistente fora do repositório. Somente ação explícita de desconectar remove a sessão.
5. O fluxo não envia mensagens automaticamente durante o diagnóstico ou o pareamento.
6. A verificação em produção registra o resultado de `/health`, `/status`, geração do QR e pareamento; se o acesso ao Railway faltar, a story permanece bloqueada e não é marcada como concluída.

## Dev Notes

O print mostra `Serviço indisponível` e a mensagem de que a URL abre o site. O diagnóstico anterior encontrou HTML em `/health` no domínio `vinidom-production.up.railway.app`, ao passo que `whatsapp-service/server.js` implementa `/health` em JSON, `/status` e `/qr`. O frontend `src/components/WhatsAppHub.jsx` chama `api/whatsapp-web.js`, que usa a URL e o segredo privados em `integration_settings`. O Dockerfile raiz foi acrescentado na correção anterior, mas sua presença no Git não comprova que o Railway esteja usando esse processo. A infraestrutura deve ser examinada antes de escolher a configuração exata; não supor que um novo commit faça o serviço correto subir automaticamente.

## Testing

- Serviço: `GET /health` deve ter `Content-Type: application/json` e `{ "ok": true }`.
- Integração autenticada: `/status` evolui até `qr_pending`, `/qr` devolve uma imagem válida; segredo incorreto é rejeitado.
- Interface móvel: QR legível; após leitura, `connected` com número; nova consulta após reinício mantém a sessão.
- Regressão: `npm run lint`, `npm test`, `npm run build` onde aplicáveis.
